# UPGP proving ground: what the run actually produced

**Date:** 2026-11-15
**Who:** build seat, by direct execution on this host (Apple Silicon, macOS/darwin).
**Scope:** UPGP proving-ground suite as it exists in `labs/workspaces/upgp-proving-ground`, plus the governed-memory gate harness added to it.
**Why:** the suite was reporting success it had not earned. Two defects were found and repaired; the numbers below are from runs made after the repair, and the pre-repair numbers are kept so the difference is visible.

**Status:** the governed-memory gate is wired and passing. The UPGP side-channel axis is **not stable** and cannot be cited as a containment result on this host. Twelve of UPGP's fifteen named vectors are constants, not measurements.

> Per UPGP's own `AGENTS.md`, "shallow Python/Rust scripts and legacy DB benchmarks are strictly banned as primary evidence" and architectural alignment requires the 14-Gate Blackbox Gauntlet. Nothing in this document is architectural proof. It is a run report on test harnesses, and it is labelled as such.

---

## 1. Two fail-open defects found

### 1.1 The TypeScript suite printed `FAIL` and exited `0`

`tests/UPGPProvingGround.test.ts` computed the F-test ratio, printed `[Axis 2] ... -> FAIL`, and then fell through to `console.log("AUDIT COMPLETE")` with process exit code `0`. Any caller reading only the exit code saw success.

Reproduced four times before the repair:

| Run | Axis 1 (Welch t) | Axis 2 (F ratio) | Exit |
|---|---|---|---|
| 1 | 0.9382 PASS | 201.8190 FAIL | 0 |
| 2 | 1.7524 PASS | 17.2284 FAIL | 0 |
| 3 | 1.4149 PASS | 23.9196 FAIL | 0 |
| 4 | 5.2175 … | 5.2175 FAIL | 0 |

**Repair:** the suite now collects `failures[]`, tracks both axes, sets `process.exitCode = 1` when any axis or any *measured* vector fails, and prints `Measured | Not measured | Failures` counts.

### 1.2 The Python runner computed failure and still exited `0`

`ops/scripts/run_upgp_full_test_gauntlet.py` computed `all_passed`, printed `❌ ... encountered failures`, and returned `None` from `main()`. It also dispatched four pre-written speech lines claiming "100 percent perfection" regardless of the result.

**Repair:**
- `main()` returns `0`/`1` and `raise SystemExit(main())`.
- Speech is generated by `build_speeches(passed, detail)` from the measured return codes and counts. It states what happened, and it says `FAIL` when the run failed.
- The verdict also requires the red-team harness to report a clean result (`0 ESCAPES` / `100% PASSED`), rather than accepting a bare exit code.
- The measured values are written into the run log as `MEASURED VALUES: z3_rc=… ts_rc=… red_rc=… measured=… not_measured=… red_clean=…`.

### 1.3 Proof that the runner now fails closed

A `node` shim was placed ahead of the real binary, returning exit `1` for `UPGPProvingGround.test.ts` only:

```
PATH="$SHIM:$PATH" python3 ops/scripts/run_upgp_full_test_gauntlet.py
EXIT=1
```

and the run log recorded:

```
MEASURED VALUES: z3_rc=0 ts_rc=1 red_rc=0 measured=1 not_measured=0 red_clean=True
FINAL RESULT: FAILED
```

The unshimmed run in the same session recorded:

```
MEASURED VALUES: z3_rc=0 ts_rc=0 red_rc=0 measured=3 not_measured=12 red_clean=True
FINAL RESULT: PASSED
```

Both directions are demonstrated, not asserted.

## 2. Axis 2 is not a stable measurement on this host

With the harness now honest, the same binary produces wildly different F ratios across runs:

| Run | Axis 2 ratio | Threshold | Verdict |
|---|---|---|---|
| pre-repair 1 | 201.8190 | < 1.50 | FAIL |
| pre-repair 2 | 17.2284 | < 1.50 | FAIL |
| pre-repair 3 | 23.9196 | < 1.50 | FAIL |
| post-repair 1 | 5.9158 | < 1.50 | FAIL |
| post-repair 2 (full runner) | 1.3966 | < 1.50 | PASS |

The ratio is a comparison of sample variances from `N = 500` timing rounds per branch, measured in the same process on a shared, non-real-time OS. A 100× swing between runs means the statistic is dominated by scheduler and cache noise, not by the branch under test.

**Conclusion we are willing to defend:** Axis 2 neither passes nor fails reliably here. It is **NOT_MEASURED** for the purpose of any security claim, and a single green run must not be quoted. A meaningful version requires pinned cores, a real-time scheduler, far more samples, and a null-distribution calibration.

Axis 1 (Welch t) stayed below 1.96 on every run observed, including the noisy ones. That is weak evidence of timing indistinguishability, not proof.

## 5. What this run does not establish

- **No architectural proof.** UPGP's own law requires the 14-Gate Blackbox Gauntlet. This is a harness run.
- **No stable side-channel result.** Axis 2 is unusable on this host, as shown in §2.
- **No independent witness.** Everything was executed by the same seat that wrote the harnesses, on one machine. Invariant B (independent adversarial challenge) is not satisfied.
- **Twelve vectors have never been implemented.** Labelling them `NOT_MEASURED` removes a false claim; it does not add coverage. If those names are to remain in the product, each needs a real body.
- **The 30M model is a plurality vote**, not PBFT, and is labelled that way in the repaired gauntlet.
