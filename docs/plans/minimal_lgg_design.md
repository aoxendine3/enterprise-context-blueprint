# Minimal Living Goal Graph (MLGG) Design \n\n## Goal \n- Keep the core idea of a *goal → decision/action → evidence* directed acyclic graph. \n- Use cryptographic hashes for each node to guarantee provenance. \n\n## Node Types \n1. **GoalNode** – high‑level objective. \n   - `id`: SHA‑256 hash of (`title` + `parent_hash`). \n   - `title`: short description. \n   - `timestamp`. \n   - `persona_lock_hash` (anchor to the immutable persona node). \n2. **DecisionNode** – tool call, code edit, or reasoning step. \n   - `parent_hash`: hash of the preceding node (goal or previous decision). \n   - `action_desc`: free‑text description. \n   - `hash`: SHA‑256 of (`parent_hash` + `action_desc` + `output_hash`). \n3. **EvidenceNode** – any file, artifact, or audio created. \n   - `file_path`. \n   - `content_hash`: SHA‑256 of the file bytes. \n   - `linked_decision_hash`. \n\n## Minimal Consistency Check \nBefore a new **GoalNode** is persisted we compute: \n```
agg = SHA256( concat( persona_lock_hash , latest_decision_hash ) )
```\nIf `agg` equals the stored `expected_agg` on the persona‑lock node, the goal is accepted; otherwise we reject and log to `memory/catch_log/consistency_fail.log`. This is a *single* hash check – no audio voting required for every goal. \n\n## Trinity Gate Integration (light) \n- The Trinity Gate will still be used for **high‑impact actions** (e.g., submitting to external services, deleting persistent data). \n- For routine goal creation we only emit a short audio note from Maxx (see below) to satisfy the “no silence” rule. \n\n## Evidence Auto‑Registration (wrapper) \nWrap `write_to_file` so that whenever a file is created we: \n1. Write the file. \n2. Compute its SHA‑256. \n3. Insert an `EvidenceNode` linked to the current decision. \n\n## Compression Daemon (optional) \nA lightweight background process runs every 500 steps: \n- Collapses a linear chain of `DecisionNode`s into a single **CompressedNode** containing only the aggregate hash. \n- Updates the DAG pointer so future look‑ups stay O(log N). \nThis daemon can be disabled via a flag if latency becomes a concern. \n\n## Retrieval API \n```python\ndef get_context(goal_id: str) -> dict:\n    """Return the latest decision hash and any linked evidence for a goal."""\n    path = dag.find_path(goal_id)\n    latest = path[-1]  # last DecisionNode\n    evidence = dag.get_evidence(latest.hash)\n    return {"latest_decision": latest.hash, "evidence": evidence}\n```\nAll agents will call this function before performing a new action, guaranteeing they operate on the exact prior state. \n\n## Metrics to Track (as Grok suggested) \n- **Retrieval latency** (target < 200 ms). \n- **Consistency pass rate** (target ≥ 99%). \n- **Reconstruction ability** – can we rebuild any output file from the DAG alone? (100 % verification).\n\n## Next Implementation Steps \n1. Add `GoalNode` and `DecisionNode` schemas to `context_lineage_dag_engine.py`. \n2. Implement the single‑hash **consistency check** in a new module `ops/scripts/check_consistency.py`. \n3. Wrap `write_to_file` with `evidence_wrapper.py` to auto‑create `EvidenceNode`s. \n4. Deploy a tiny daemon `ops/scripts/compression_daemon.sh` (configurable). \n5. Update `trinity_gate.py` to emit a short Maxx audio confirmation for each new goal (no vote). \n6. Write unit tests in `tests/lgg_test.py` and run them via `pytest`.\n\n## Audio Confirmation (Maxx) \nWhen a goal is accepted we will run: \n```bash\nbash core/ops/scripts/agent_speak.sh maxx \"Goal '<title>' created and validated.\"\n```\nThe temporary audio file will be auto‑deleted, satisfying the “no bloat” rule.\n\n---\n*This design keeps the valuable structured graph and provenance while removing the high‑friction 2‑out‑of‑3 audio vote for every goal. It meets the collective invariants, provides auditability, and stays lightweight enough for real‑time operation.*
